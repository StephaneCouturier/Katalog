# Theme, colour derivation and icon size

![Status](https://img.shields.io/badge/Status-Draft-orange) ![Version](https://img.shields.io/badge/Version-2.13-blue) ![Implementation](https://img.shields.io/badge/Implementation-partial-yellow)

## Context

K3 (`qt_quick`) paints several surfaces that are not plain page background: the
alternating rows of a file list, the selected row, the logo band and the
Selection page surface. This spec defines **where those colours come from** and
**what the Theme setting is allowed to change**.

The rule behind it: a colour is either taken from the desktop colour scheme
through `Kirigami.Theme`, or it does not exist. Literal colour constants
(`"white"`, `"black"`, hex brand blues) do not follow the user's scheme and are
what this spec removes. *(Two accepted exceptions, each bounded by its row: the
Statistics chart series colours (`THM-C17`), and K2's Katalog Colors palette
under theme id 1 only (`THM-F4`, `THM-C19`, `THM-C20`), amended 2026-09-30.)*

**Decision of 2026-09-30 (finishing Katalog Colors).** The maintainer: "I want to
"finish" the Katalog Colors theme. This means that all items with colors (non
grey) should use a defined Katalog color. Can you assign one for all these
elements, including: background of collection name in drawer, Selection
background & selected item, section titles, for now I accept that checkbox and
other non-text object have the default dekstop theme color". On the proposed
mapping: "yes let's start with this, easier for me to look once implemented".
Under theme id 1 the coloured K3 surfaces and texts now take K2's brand palette
(`THM-F17` to `THM-F21`, `THM-C20`); non-text controls and semantic status
colours stay the desktop's (`THM-C21`). Themes 0 and 2 are unchanged.

**Decision of 2026-09-30 (finishing Desktop Theme (gray)).** The maintainer:
"good. as you define application colors, can you now complete the Desktop Theme
(grey) by attributing a grey color to the colored elements (ex: section title)".
Under theme id 2 the section titles, the selection highlight and the Selection
reminder hover now take greys derived from the desktop scheme (`THM-F17`,
`THM-F18`, `THM-F21`, amended; `THM-C22`). Its Selection page surface, logo band
and stripe were already grey (`THM-C4`, `THM-F4`). No hex literal: the palette
exception stays theme id 1 only.

**Decision of 2026-10-01 (list background, gray highlight and band).** Three
changes, approved by the maintainer on 2026-10-01. (1) The empty area below the
last row of the Search results, Explore file and Explore folder lists takes a
theme-dependent colour (`THM-F22`, `THM-C23`): "I want that for the Katalog
Colors theme actually. for the 2 desktop themes, put the non-alternate so whitish
row color (in light mode)", then "ok". (2) Under theme id 2 on a light desktop
the selection highlight is lightened (`THM-F18`, amended): "the color for
selection ... in desktop theme gray is too dark", option "1" chosen. (3) Under
theme id 2 on a light desktop the drawer collection-name band takes that same
highlight colour (`THM-F20`, `THM-C4`, amended): "put that same color for the
background of the collection name in the drawer".

## Scope at a glance

**In scope:** K3 colour derivation — the file-list row pair, and the reach of the
three `Settings/Theme` values on K3's derived colours — and the **icon size
preference** of `THM-F7`, which belongs here because it is stored in the same
`Settings/Theme*` key family and shared with K2 — and the **Explore folder list's** row surfaces
(`THM-F8`, `THM-F9`, `THM-C11`) — and the surface of the **Selection page's
`SEL-F5` reminder row** (`THM-F10`, `THM-C13`, `THM-C14`). *(Scope widened
2026-09-12, first from colour derivation alone, then to the folder list; widened
again 2026-09-21 to the reminder row.)* — and the operational goal `THM-O2`,
whose delivery is owned by `SpecK3Deployment.md` (`DPL-F5`) — and the
**light/dark variant of the fallback icon set** (`THM-F11`). *(Widened
2026-09-23, twice.)* Recorded as `[Backlog]` only, 3.1 candidates, not authorised
for 3.0: a Katalog colour-scheme setting (`THM-F12`, `THM-C15`) and a startup
workaround for a misread portal preference (`THM-F13`, `THM-C16`). *(Added
2026-09-24.)* — and the **Statistics page chart**'s light/dark theme (`THM-F14`,
`THM-C17`). *(Widened 2026-09-27.)* — and the **odd-row stripe colour per
`Settings/Theme` value** (`THM-F4`, `THM-C2`, `THM-C19`). *(Amended 2026-09-30:
the Theme setting now changes the file-list odd-row colour; before, it did not.)*
— and the **Katalog Colors palette under theme id 1** for section titles, the
selection highlight, the Selection page surface, the drawer logo band and the
Selection reminder hover (`THM-F17` to `THM-F21`, `THM-C20`, `THM-C21`).
*(Widened 2026-09-30.)* — and the **background of the empty area below the last
row** of the Search results, Explore file and Explore folder lists (`THM-F22`,
`THM-C23`). *(Widened 2026-10-01.)*

**Out of scope (non-goals):**

- **K2 (`qt_widgets`)** — in maintenance mode. It shares the same
  `Settings/Theme` key and keeps its own Katalog Colors rendering, untouched
  (`THM-C5`).
- **Icon theme** — icon set selection is not governed here, **except** that the fallback icon set follows light/dark (`THM-F11`); `THM-F7` sets a
  size, never which icon set is used.
- **Which K3 views honour `THM-F7`** — see `THM-C10`.
- **File-list text colour** — rows keep `Kirigami.Theme.textColor` under every
  Theme value; K2's `#333` (from its Katalog Colors light stylesheet) is not
  ported (`THM-C19`).
- **Removing the "Katalog Colors" entry from the Settings combo** — explicitly
  future work, not authorised by this spec (`THM-C3`).
- Typography, spacing, and any other non-colour theming.
- **Non-text controls and semantic colours under theme id 1** — checkboxes, radio
  buttons, focus rings, progress bars, scrollbars and other non-text controls,
  and semantic status colours, keep the desktop's colours under every Theme
  value (`THM-C21`; accepted by the maintainer "for now", 2026-09-30).

> **Note on the stored default.** `Settings/Theme` defaults to `1` for a new K3
> profile. Under `THM-C2` that default renders K2's Katalog Colors palette on
> the file-list odd-row stripe (`THM-F4`), on the surfaces of `THM-F17` to
> `THM-F21` and on the list background of `THM-F22`, and theme `0` everywhere
> else (amended 2026-09-30; `THM-F22` added 2026-10-01). This is
> recorded, not changed: altering the default value is not authorised here. Beta
> testers whose stored value is `1` will see the brand colours after this change;
> no key is added or rewritten.

## Constructional requirements — *how it is built / limits / MUST-NOTs*

Boundaries and implementation constraints, not user-visible behaviour.

| ID | Requirement | Status |
|----|-------------|--------|
| THM-C1 | **Both** colours of the `THM-F1` pair are defined **once**, in `Main.qml` at `applicationWindow()` scope, and consumed from there by the three list delegates — Search results, Explore files and Explore folders (`THM-C11`). A page or delegate MUST NOT hardcode, re-derive or locally redefine either colour — including the odd-row stripe of `THM-F4` (`rowStripeColor`), which is theme-dependent but still defined once (`THM-C19`). One definition, three consumers. *(Amended 2026-09-30: the second colour was the Window colour. Amended 2026-10-01: "two consumers" became three, aligning with `THM-C11` / `THM-F8`.)* | [Planned] |

For everything else, theme id 1 renders **exactly** as theme id 0 — the accent-derived variant — and **not** as theme id 2. *(Amended 2026-09-30, twice: first the stripe alone was added; then, at the maintainer's request to "finish" Katalog Colors, `THM-F17` to `THM-F21`.
