Specifications

Every specification page lives in docs_src/docs/development/. This page is the index: new specifications are added here, not to the sidebar.

A specification defines what Katalog is required to do. The code is never the source of requirements — it may contain unauthorised or buggy behaviour. Where a specification and the code disagree, the specification is what was agreed.

Conventions​

  • Requirement IDs use a per-page prefix (STI-, DSR-, OPQ-…) and are permanent: never renumbered, never reused, retired as [Removed] rather than deleted.
  • Requirements are grouped as Operational (-O, why and for whom), Functional (-F, what the system does) and Constructional (-C, how it is built, and the MUST-NOTs).
  • Each row carries a status: [Implemented] / [Planned] / [Backlog] / [Removed].
  • Specification pages are English only.

Page design rules are in Dev-Documentation.
