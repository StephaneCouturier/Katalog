Theme, colour derivation and icon size

Context​

K3 (qt_quick) paints several surfaces that are not plain page background: the alternating rows of a file list, the selected row, the logo band and the Selection page surface. This spec defines where those colours come from and what the Theme setting is allowed to change.

The rule behind it: a colour is either taken from the desktop colour scheme through Kirigami.Theme, or it does not exist. Literal colour constants ("white", "black", hex brand blues) do not follow the user's scheme and are what this spec removes. (Two accepted exceptions, each bounded by its row: the Statistics chart series colours (THM-C17), and K2's Katalog Colors palette under theme id 1 only (THM-F4, THM-C19, THM-C20), amended 2026-09-30.)

Decision of 2026-09-30 (finishing Katalog Colors). The maintainer: "I want to "finish" the Katalog Colors theme. This means that all items with colors (non grey) should use a defined Katalog color. Can you assign one for all these elements, including: background of collection name in drawer, Selection background & selected item, section titles, for now I accept that checkbox and other non-text object have the default dekstop theme color". On the proposed mapping: "yes let's start with this, easier for me to look once implemented". Under theme id 1 the coloured K3 surfaces and texts now take K2's brand palette (THM-F17 to THM-F21, THM-C20); non-text controls and semantic status colours stay the desktop's (THM-C21). Themes 0 and 2 are unchanged.

Decision of 2026-09-30 (finishing Desktop Theme (gray)). The maintainer: "good. as you define application colors, can you now complete the Desktop Theme (grey) by attributing a grey color to the colored elements (ex: section title)". Under theme id 2 the section titles, the selection highlight and the Selection reminder hover now take greys derived from the desktop scheme (THM-F17, THM-F18, THM-F21, amended; THM-C22). Its Selection page surface, logo band and stripe were already grey (THM-C4, THM-F4). No hex literal: the palette exception stays theme id 1 only.

Decision of 2026-10-01 (list background, gray highlight and band). Three changes, approved by the maintainer on 2026-10-01. (1) The empty area below the last row of the Search results, Explore file and Explore folder lists takes a theme-dependent colour (THM-F22, THM-C23): "I want that for the Katalog Colors theme actually. for the 2 desktop themes, put the non-alternate so whitish row color (in light mode)", then "ok". (2) Under theme id 2 on a light desktop the selection highlight is lightened (THM-F18, amended): "the color for selection ... in desktop theme gray is too dark", option "1" chosen. (3) Under theme id 2 on a light desktop the drawer collection-name band takes that same highlight colour (THM-F20, THM-C4, amended): "put that same color for the background of the collection name in the drawer".

Reading the requirement IDs. Each requirement has a permanent ID. IDs are never renumbered or reused; a retired requirement is marked [Removed], not deleted. Status is one of [Implemented] / [Planned] / [Backlog] / [Removed].

Scope at a glance​

In scope: K3 colour derivation — the file-list row pair, and the reach of the three Settings/Theme values on K3's derived colours — and the icon size preference of THM-F7, which belongs here because it is stored in the same Settings/Theme* key family and shared with K2 — and the Explore folder list's row surfaces (THM-F8, THM-F9, THM-C11) — and the surface of the Selection page's SEL-F5 reminder row (THM-F10, THM-C13, THM-C14). (Scope widened 2026-09-12, first from colour derivation alone, then to the folder list; widened again 2026-09-21 to the reminder row.) — and the operational goal THM-O2, whose delivery is owned by SpecK3Deployment.md (DPL-F5) — and the light/dark variant of the fallback icon set (THM-F11). (Widened 2026-09-23, twice.) Recorded as [Backlog] only, 3.1 candidates, not authorised for 3.0: a Katalog colour-scheme setting (THM-F12, THM-C15) and a startup workaround for a misread portal preference (THM-F13, THM-C16). (Added 2026-09-24.) — and the Statistics page chart's light/dark theme (THM-F14, THM-C17). (Widened 2026-09-27.) — and the odd-row stripe colour per Settings/Theme value (THM-F4, THM-C2, THM-C19). (Amended 2026-09-30: the Theme setting now changes the file-list odd-row colour; before, it did not.) — and the Katalog Colors palette under theme id 1 for section titles, the selection highlight, the Selection page surface, the drawer logo band and the Selection reminder hover (THM-F17 to THM-F21, THM-C20, THM-C21). (Widened 2026-09-30.) — and the background of the empty area below the last row of the Search results, Explore file and Explore folder lists (THM-F22, THM-C23). (Widened 2026-10-01.)

Out of scope (non-goals):

  • K2 (qt_widgets) — in maintenance mode. It shares the same Settings/Theme key and keeps its own Katalog Colors rendering, untouched (THM-C5).
  • Icon theme — icon set selection is not governed here, except that the fallback icon set follows light/dark (THM-F11); THM-F7 sets a size, never which icon set is used.
  • Which K3 views honour THM-F7 — see THM-C10.
  • File-list text colour — rows keep Kirigami.Theme.textColor under every Theme value; K2's #333 (from its Katalog Colors light stylesheet) is not ported (THM-C19).
  • Removing the "Katalog Colors" entry from the Settings combo — explicitly future work, not authorised by this spec (THM-C3).
  • Typography, spacing, and any other non-colour theming.
  • Non-text controls and semantic colours under theme id 1 — checkboxes, radio buttons, focus rings, progress bars, scrollbars and other non-text controls, and semantic status colours, keep the desktop's colours under every Theme value (THM-C21; accepted by the maintainer "for now", 2026-09-30).

Note on the stored default. Settings/Theme defaults to 1 for a new K3 profile. Under THM-C2 that default renders K2's Katalog Colors palette on the file-list odd-row stripe (THM-F4), on the surfaces of THM-F17 to THM-F21 and on the list background of THM-F22, and theme 0 everywhere else (amended 2026-09-30; THM-F22 added 2026-10-01). This is recorded, not changed: altering the default value is not authorised here. Beta testers whose stored value is 1 will see the brand colours after this change; no key is added or rewritten.

Operational requirements — why / for whom​

Goals in real use, independent of how they are built.

IDRequirementStatus
THM-O1A user scanning a long file list can tell one row from the next at a glance, and does not lose the line they are reading — under their own desktop colour scheme, light or dark, and whichever Theme value is stored.[Planned]
THM-O2A user who has set their system to dark (or light) sees K3 in that mode as a whole window, not a mix of dark surfaces and light controls — in packaged builds on non-Plasma Linux desktops, on Windows and on macOS, as well as on Plasma. Delivered by packaging, per DPL-F5 / DPL-C6 (SpecK3Deployment.md).[Planned]

Functional requirements — what the system does​

THM-F123.1 candidate. The Settings page offers a choice of Katalog's colour scheme: System (follow the desktop — the default), Light or Dark. Constructional requirements — how it is built / limits / MUST-NOTs​

Boundaries and implementation constraints, not user-visible behaviour.

IDRequirementStatus
THM-C1Both colours of the THM-F1 pair are defined once, in Main.qml at applicationWindow() scope, and consumed from there by the three list delegates — Search results, Explore files and Explore folders (THM-C11). A page or delegate MUST NOT hardcode, re-derive or locally redefine either colour — including the odd-row stripe of THM-F4 (rowStripeColor), which is theme-dependent but still defined once (THM-C19). One definition, three consumers. (Amended 2026-09-30: the second colour was the Window colour. Amended 2026-10-01: "two consumers" became three, aligning with THM-C11 / THM-F8.)[Planned]
THM-C2Katalog Colors (theme id 1) applies K2's brand palette in K3 to exactly these: the file-list odd-row stripe (THM-F4), section titles (THM-F17), the selection highlight (THM-F18), the Selection page surface (THM-F19), the drawer logo band (THM-F20), the Selection reminder hover (THM-F21) and the list background below the last row (THM-F22, which takes the THM-F4 stripe). It MUST NOT apply a brand override anywhere else — in particular not to the even-row (View) colour, text colours other than THM-F17, or the items of THM-C21. For everything else, theme id 1 renders exactly as theme id 0 — the accent-derived variant — and not as theme id 2. (Amended 2026-09-30, twice: first the stripe alone was added; then, at the maintainer's request to "finish" Katalog Colors, THM-F17 to THM-F21. Amended 2026-10-01: THM-F22 added, maintainer-approved.)[Planned]
THM-C3The stored value Settings/Theme = 1 and the Katalog Colors entry in the Settings combo are preserved. No user-visible string is added, changed or removed by this spec, and no translation slot is spent. In K3 the entry's visual effect is the brand palette of THM-C2 (THM-F4, THM-F17 to THM-F22). (Amended 2026-09-30, twice: previously "the entry simply has no visual effect in K3", then "only the THM-F4 stripe".) Removing it is out of scope (see Scope).[Planned]
THM-C4Theme id 2, Desktop Theme (gray), keeps its existing distinct derivation from the desktop background (no hue) for the Selection page surface, and for the logo band on a dark desktop. On a light desktop the logo band is the theme id 2 selection grey of THM-F18, derived from Kirigami.Theme.textColor — still no hue, no hex literal (THM-F20, THM-C22). (Amended 2026-09-30: was "Unchanged by this spec"; theme id 2 now also has its own greys for titles, highlight and reminder hover, THM-F17, THM-F18, THM-F21, THM-C22. THM-C5K2 (qt_widgets) MUST NOT be modified by this work. (Amended 2026-09-30, twice.)[Planned]
THM-C6The View colour set MUST be entered in a scope narrow enough that it does not leak onto surrounding items — inherit: false on the item that reads it, so sibling and parent surfaces keep the Window colour set.[Planned]
THM-C7The item that reads the View colour set MUST NOT be hidden (visible: false). A hidden item is given no resolved palette by the KDE platform theme and its background colour reads back as opaque black, which paints the first row of every file list black on a light desktop. This failure does not reproduce under QT_QPA_PLATFORM=offscreen, where a hidden item still returns the correct colour, so it cannot be caught by an offscreen run — it must be checked against the real desktop.[Planned]
THM-C8THM-F7 is stored in the existing key Settings/ThemeBiggerIconSize, the one K2 already writes (qt_widgets/mainwindow_tab_settings.cpp:624-645, restored at qt_widgets/mainwindow_setup.cpp:384), so both versions share one preference. K2 stores the Qt check state (2 / 0) and reads it with toBool(), so a K3 boolean round-trips through it; K3 MUST NOT introduce a second key, nor change the value encoding.[Planned]
THM-C9THM-F7 reuses K2's existing label Use bigger icon size byte-for-byte — approved per string by the user on 2026-09-12 — so the 30 existing translations carry it and no slot is spent. No other new string is authorised by these rows. K2 MUST NOT be modified, per THM-C5.[Planned]
